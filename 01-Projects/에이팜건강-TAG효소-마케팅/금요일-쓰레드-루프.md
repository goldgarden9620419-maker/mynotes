# 국민 T.A.G 효소 — 금요일 개인 쓰레드 루프

`marketing-loops` 스킬 기반. 매주 금요일 자동으로 실행되어 개인 Threads 계정용 홍보 글 초안을 만들어둔다.

**게시 방식 (2026-10-02부터 Typefully MCP로 전환)**: 이 세션에 Typefully(소셜 미디어 예약/발행 MCP)가 연결되면서, kim_jade0419 Threads 계정이 이미 연동되어 있는 것을 확인했다. 이제 클로드가 `create_draft`로 본문+첫댓글(답글 형태)을 만들고 `confirm_publish: true`로 **직접 게시**할 수 있다 (social_set_id: 337240). 과거 PowerShell 스크립트 방식(샌드박스가 `graph.threads.net`에 접근 못해 사용자가 직접 실행해야 했던 방식)은 더 이상 필요 없지만, 혹시 몰라 아래에 백업 정보로 남겨둔다.

**게시 전 확인 원칙은 그대로 유지**: 기술적으로 클로드가 직접 게시 가능해졌어도, 실제 게시 직전에는 항상 본문/톤을 사용자에게 보여주고 "게시해도 될까요?" 확인을 받은 뒤에만 `confirm_publish: true`로 진행한다 (2026-09-06 사용자가 "항상 사람 확인 후 게시"를 선택한 원칙 유지).

**(백업) 과거 PowerShell 방식**: 사용자 컴퓨터의 `쁘띠앤쓰레드자동화` 폴더 스크립트로 게시하던 방식. Typefully가 오류나거나 막힐 경우에만 사용.

**구매 링크 정책**: 본문에는 링크를 넣지 않는다 (도달 감소 방지). 대신 **게시 직후 첫 댓글**로 공식 제품 페이지 링크를 단다. 첫 댓글도 같은 스크립트 방식으로 게시 가능 (creation_id 대신 게시된 글의 media id를 reply_to_id로 사용).

**보유 스크립트** (사용자 컴퓨터의 `쁘띠앤쓰레드자동화` 폴더에 저장됨):
- `post_to_threads.ps1` — 텍스트 글 게시
- `post_video_to_threads.ps1` — 영상 글 게시 (video_url 전달, 처리 완료까지 자동 폴링 후 게시)
- `post_reply_to_threads.ps1` — 댓글(첫 댓글 구매 링크 등) 게시

**제품 영상**: `higgsfield-product-ad-pipeline` 스킬로 간단한 히어로샷 영상(5초, 9:16)을 만들어 캡션과 함께 게시 가능. 기존 스토리보드/씬이미지(2026-08-09 제작분)를 재사용하면 새 제품 사진 업로드 없이도 빠르게 만들 수 있다. 영상 게시는 Typefully의 `create_media_upload`로 영상을 업로드해 media_id를 받은 뒤, `create_draft`의 threads posts에 `media_ids`로 붙여서 올린다.

**다음 실행 예정 메모 (2026-10-02 사용자 요청)**: 다음 금요일 루프(10/9)는 텍스트 각도 대신 **짧은 제품 영상 게시**로 진행한다 (사용자가 "짧은 영상도 좀 들어갔으면 좋겠다"고 요청, 다음 루프 때 하기로 결정). 기존 스토리보드 자산을 재사용해 5초 내외 영상 제작 → 짧은 캡션과 함께 Typefully로 게시 → 첫 댓글에 구매 링크.

## 루프 명세

### The TAG-enzyme Friday Threads loop
- **Check cadence**: 매주 1회 (금요일 오전 9시 KST)
- **Acts when**: 대기 중(미게시) 초안이 1편 미만일 때만 새로 작성. 이미 대기 중인 초안이 있으면 스킵 (밀어내기 방지).
- **Purpose**: 담당자 개인 Threads 계정에서 국민 T.A.G 효소를 자연스럽게 홍보할 초안을 매주 준비해둔다.
- **Skills used**: `copywriting`, `social` (또는 직접 작성)
- **Loop body**:
  1. `.agents/loops/tag-enzyme-threads.json`에서 대기 중 초안 개수 확인
  2. 1편 이상이면 스킵
  3. 미달이면 `product-marketing.md`(이 프로젝트 폴더)를 참고해, 매주 다른 각도로 글 작성 (예: 원료 소개 각도, "이런 분들께 추천" 체크리스트 각도, 사과맛/먹는 경험 각도 등 — `used_angles`와 중복되지 않게 로테이션). 본문에는 구매 링크를 넣지 않는다.
  4. 반드시 재직 사실 고지 문구 포함, 신규 효능 주장 생성 금지 (공식 페이지 표현 범위 내에서만)
  5. `01-Projects/에이팜건강-TAG효소-마케팅/`에 노트로 저장(본문 + 첫 댓글용 구매 링크 문구 별도 표기) → git commit + PR (병합은 안 함)
  6. 사용자에게 초안 내용을 보여주고 게시 확인을 받은 뒤, 승인되면 Typefully `create_draft`(social_set_id 337240, threads posts: [본문, 첫댓글], `confirm_publish: true`)로 직접 게시. `publish_state`가 `in_progress`면 `get_draft`로 완료 확인 후 게시 URL을 노트/상태 파일에 기록.
  7. `tag-enzyme-threads.json`의 `used_angles`·`pending_drafts`·`published`·`last_run` 갱신
- **Self-check**: 이번 글이 회사 공식 페이지에 없는 새로운 효능·기능성 주장을 하고 있지 않은가? 재직 고지 문구가 포함됐는가? 지난 4주와 같은 각도를 반복하지 않는가?
- **State / idempotency**: `.agents/loops/tag-enzyme-threads.json` — `used_angles`(로테이션 dedupe), `pending_drafts`, `last_run`
- **Stop / bail-out**:
  - **Typefully로 직접 게시는 가능하지만, 게시 직전 항상 사용자에게 본문을 보여주고 명시적 확인을 받은 뒤에만 실행한다** — 확인 없이 스스로 `confirm_publish: true`를 쓰지 않는다
  - **PR 병합도 하지 않는다** — 커밋/PR 생성까지만
  - 사용 가능한 각도를 4주 안에 다 썼는데 새 각도가 안 나오면, 억지로 만들지 말고 사용자에게 "각도가 소진됐다"고 알리고 다음 방향(신제품 정보 추가 필요 등)을 물어본다
  - 오류 발생 시 조용히 넘어가지 않고 보고
- **Output**: vault 노트 파일(Threads 초안 텍스트) + git PR + 사람에게 요약 알림
