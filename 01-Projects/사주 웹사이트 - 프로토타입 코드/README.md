# 사주 웹사이트 프로토타입 코드

DB를 코드에서 분리해 JSON 파일로 관리하는 버전입니다.

> **2026-08-04 업데이트**: 27명 → 65명(60갑자 100% 커버) → 121명 → 116명(정치인 4명·이재용 제거) → **161명**(전 갑자 최소 2명)으로 순차 확장/정리.

## 파일 구성
- `celebrities.json` — 유명인 161명 데이터 (이름, 일주, 성공스토리, 습관, 모토) — 60갑자 전체 커버, 갑자당 2~3명
- `ohang_copy.json` — 오행(木火土金水) 5개 설명 카피
- `match.py` — 매칭 로직 (일주 정확 일치 → 없으면 오행 기준 폴백, 생년월일 해시 기반 고정 시드 적용). Python/서버용 참고 구현
- `index.html` — **프론트엔드 프로토타입** (입력폼 + 결과카드). 서버·빌드 없이 브라우저에서 파일 더블클릭으로 바로 실행됨

## 실행 방법
```bash
# 백엔드 로직만 확인
pip install lunar_python
python3 match.py

# 프론트엔드 프로토타입
open index.html   # 또는 브라우저에서 파일 직접 열기
```

## index.html 동작 방식
- 생년월일을 입력하면 JS에서 바로 일주(日柱)를 계산 (서버/API 없이 클라이언트에서 완결)
- **일주 계산 방식**: 율리우스일(JDN)을 구해 `(JDN + 49) mod 60`으로 60갑자 인덱스 계산. 이 offset(49)은 `match.py`(lunar_python 기준)의 계산 결과 28개 샘플 날짜(1769~1993년)와 전수 대조해서 검증됨 — 일주는 절기(월 경계)와 무관하게 날짜만으로 정해지는 60일 주기라, 복잡한 만세력 라이브러리 없이도 JS 몇 줄로 정확히 계산 가능
- 정확 일치 유명인이 없으면 오행 기준으로 폴백하되, FNV-1a 해시 + mulberry32 PRNG로 시드를 고정해 같은 날짜는 항상 같은 결과가 나오도록 함 (`match.py`의 Python 시드 로직과 동일한 목적)
- DB(`celebrities.json`, `ohang_copy.json`)는 `index.html` 안에 그대로 인라인되어 있음 (파일을 직접 열어도 fetch 없이 동작하게 하기 위함) → 데이터 수정 시 JSON 파일과 `index.html` 양쪽에 반영 필요 (추후 실서비스에서는 이 중복을 없애고 API/빌드 시점 주입으로 전환해야 함)
- **결과 카드 이미지 저장/공유**: "카드 이미지로 저장/공유" 버튼 클릭 시 `<canvas>`로 결과 카드를 직접 그려 PNG로 만듦 (html2canvas 등 외부 라이브러리 불필요). 오행별 포인트 컬러(`OHANG_COLORS`)를 적용한 그라디언트 배경에 일주 배지·오행 타이틀·키워드·명언·매칭된 유명인(최대 2명)을 그려넣음
  - **2-패스 렌더링**: 임시 캔버스로 모든 텍스트를 먼저 측정해 줄바꿈 라인 수를 계산하고, 그 값으로 카드 전체 높이를 정확히 산출한 뒤 실제 캔버스에 그림 — 유명인 모토 길이에 따라 카드 높이가 자동으로 늘어나며, 하단 텍스트가 겹치는 문제 없음
  - 생성된 이미지는 모달로 미리보기, `<a download>`로 즉시 다운로드 가능
  - `navigator.share`(Web Share API, 파일 공유 지원 시)가 있으면 "공유하기" 버튼도 노출 → 모바일에서 카카오톡/인스타그램 등으로 바로 공유 가능. 미지원 브라우저(대부분의 데스크톱)에서는 다운로드만 제공

## 검증 (Playwright 헤드리스 브라우저로 실제 확인)
- 입력폼 렌더링 정상, JS 콘솔 에러 없음
- 1955-02-24(스티브 잡스 생일) 입력 → 정확 매칭으로 **스티브 잡스 + 레오나르도 디카프리오** 2명 동시 노출 확인
- 1990-03-15 입력 → 정확 매칭으로 **비(정지훈)·박명수·칼 라거펠트** 3명 동시 노출 확인 (161명 확장 후 갑자당 최대 3명까지 매칭 가능)
- 161명 DB 기준 60갑자 100% 커버 확인 (`Object.keys(ILJU_INDEX).length === 60`), 이름 중복 없음
- 카드 이미지는 매칭 인원이 3명이어도 대표 2명만 그려 카드 가독성 유지 (`r.celebrities.slice(0, 2)`), 나머지는 페이지 결과 목록에서 전체 확인 가능
- Node.js로 `index.html`의 로직 부분만 추출해 Python(`match.py`) 계산 결과와 다수 날짜 교차검증 → 일치
- **카드 이미지 저장 기능**: "카드 이미지로 저장/공유" 클릭 → 모달에 카드 이미지 정상 표시, 다운로드 링크 동작 확인. 캔버스에서 생성된 PNG를 직접 추출해 실제 렌더링 결과(오행 배지·타이틀·키워드·명언·유명인 2명)를 시각적으로 확인
  - 최초 구현 시 유명인 박스 높이를 고정값으로 계산해 하단 "매칭 유형" 텍스트가 겹치는 버그 발견 → 2-패스(측정 후 그리기) 방식으로 재작성해 해결
  - "닫기" 버튼이 투명 배경이라 뒤 배경 텍스트가 비쳐 보이는 문제도 발견해 불투명 배경으로 수정

## 왜 JSON으로 분리했나
- 유명인 DB가 늘어날수록(60갑자 커버리지 확장 등) 코드 수정 없이 데이터만 추가/수정 가능
- 콘텐츠 담당자가 코드를 몰라도 `celebrities.json`만 편집하면 되도록
- 추후 웹 프레임워크로 이식할 때 API가 이 JSON을 그대로 응답으로 내려줄 수도 있음
