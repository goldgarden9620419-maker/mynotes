## 프로젝트 개요
- 저장소: `goldgarden9620419-maker/mynotes` (Obsidian vault, private)
- 소스 위치: `01-Projects/에이팜건강-주간자금계획-자동화/cashflow_automation` (Python 3.11 + openpyxl + APScheduler, Windows 상주 트레이 프로그램)
- 개발 브랜치: `claude/charming-clarke-f2k4zu` / 배포(사용자 PC가 Obsidian Git으로 10분마다 Pull하는) 브랜치: `claude/obsidian-usage-guide-1i4otf`
- 코드 수정 후 절차: pytest 전체 통과 → 실데이터 파이프라인 검증 → 개발 브랜치 커밋·푸시 → 같은 변경을 배포 브랜치에도 동기화(vault의 입력·상태 파일은 건드리지 않음)

## 동작 사양 (핵심)
1. 팀 지출계획(01·02 폴더)과 은행 3사 내역(03 폴더)을 취합·대조해 매주(월 09:10, 또는 "지금 실행") 자금계획을 만든다.
2. **2단계 확인 흐름**: 실행하면 먼저 `06_확인필요/확인필요_일시.xlsx` 1개를 만들어 자동으로 연다. 시트 순서 = 안내 → 확인필요 → 정기지출누락 → 정기지출분석 (2026-09-23부터 자동추정_지출목록 시트는 만들지 않음 — load_review_directives는 새 '정기지출누락' 시트와 예전 확인필요 시트 형식을 모두 읽음). 사용자가 **안내 시트 B2='예'**로 저장하면 결과를 생성한다. 결과 생성 후 재실행하면 항상 새 확인 단계부터.
2-1. **'계획 없는 실제출금' 분류 기억**(2026-09-22 사용자 요청): 확인필요 시트의 해당 행 처리 열(I, 자유 입력·노란 칸)에 분류를 적으면(예: '급여·상여') `load_unplanned_classifications`가 수확해 classify_rules.json의 `사용자분류`([{이름, 분류}])로 저장하고(`remember_custom_names`/`save_rules`), 이번 실행분에도 즉시 적용(`apply_custom_names` — 미분류·확인필요 행만)한다. classify_rows에서 사용자분류는 내장 규칙(TOP출금 월말 급여 등)보다 **최우선**이며, 분류가 지정된 거래는 '계획 없는 실제출금'에 다시 오르지 않는다.
3. 지난 확인 대비 **새 항목은 주황(FFE699)** 강조 + 안내 시트 A3와 실행창 메시지에 건수 안내.
4. **정기지출 성격**은 정기/비정기/제외 3종. 우선순위 = K4 전체 일괄 > N열 분류별(숨김 O열 기준값과 다르게 바꾼 분류만 적용) > K열 개별. K4가 켜져 있으면 L4에 실시간 경고. 수정 내용은 기준파일(정기지출분류 시트)에 저장돼 다음 실행에도 유지.
5. 정기지출 예정일이 주말·공휴일이면 **다음 영업일**(달을 넘기면 그 달 마지막 영업일)로 이동.
5-1. **실행일 당일은 실적으로 확정하지 않는다**(`actual_until`을 실행일 전날로 제한): 은행 파일에 당일 새벽 거래만 찍힌 상태에서 그날의 지급예정이 계획에서 사라지는 것을 막는다. 당일 거래 순증감은 시작잔액(계좌별시나리오는 backout_from)에서 되돌려 이중계산이 없다.
5-2a. **출발 행 2단**(두 시트 공통): 6행 = 전일 마감 계좌별 실잔고 — **계획은 여기서 출발**. 7행 = 오늘 은행 확인 계좌별 실잔고 + 당일 실제 입금(온라인/기타)·출금(참고 표시 — forecast["today_actual"], 체인에 넣지 않음. 당일 순증감은 net_actual 백아웃으로 이미 상쇄). 계획 행은 8~35행(두 시트 1:1, 13주 SUMIFS·요약 B14/B15·붉은 상자·숨김도 8~35 기준, freeze C8/D8). 첫 계획 행 기초 = `={close}6`(기준일<실행일이면 시작잔액 리터럴).
5-2b. **계획 반영 대상**: ① 팀 지출예정(취합) ② 주간조정 ③ 온라인 예상입금(업로드된 은행 이력의 12주 요일평균 × 반영률). **정기지출 추정은 계획에 반영하지 않는다**(2026-09-23 사용자 재확정 — 모드와 무관하게 코드에서 자동추정을 adjustments에 넣지 않음; 목록 파일은 누락 대조 기준으로만 유지·갱신). 정기지출 누락 의심은 확인 파일 **'정기지출누락' 시트**(전용, `RECURRING_MISSING_SHEET`)에서 확인받고 '계획에 반영' 지시만 adjustments("확인필요 지시 반영")로 들어간다. `weekly_recurring_check(drafts_reflected=False)`라 '반영' 표시 행도 팀 파일에 없으면 전부 누락 의심. 경영보고의 '정기지출 체크' 시트도 제거(결과파일에 정기지출 없음).
5-2d. **실행일 이전 지급일의 지출계획은 반영하지 않는다**(2026-09-23 사용자 확정, `forecast_engine.drop_past_plans`): build_forecast·next4w·경영보고 ④ 지출예정 표(week_start를 실행일로 클램프)에는 반영일 ≥ 실행일 항목만 넣는다. 은행 대조(match_payments '예정지출 미출금' 알림)와 당일 대조는 전체 목록으로 계속한다.
5-2c. **실행일 = 실적 마감, 미집행은 익일 이월**(2026-09-21 사용자 최종 확정) — 단 **마감 시각(config `intraday.close_after`, 기본 17:00) 이후 실행이면서 은행 파일에 당일 거래가 있을 때만** 적용한다(2026-09-22 확정): 17시 이전 실행(아침·낮)은 새벽 자동입금이 찍혀 있어도 app이 `intraday_enabled=False`로 넘겨 실행일 행이 송금예정·조정 계획 그대로 표시되고 확인 단계의 '당일 지출·실제 차이' 행도 만들지 않는다. intraday_actuals 자체에도 당일 거래 부재 시 None 게이트가 있고, **당일 대조(intraday_check)는 시각과 무관하게 항상 계산**해 경영보고 ④ 실지출 열에 쓴다. 마감 시: 실행일 행은 은행 파일 그대로 실적으로 마감한다 — 순현금흐름 = 실제 입출금만(송금예정·조정추정 미포함), 온라인/확정 열 = 실제 값, 지출 열 = 집행·계획외 실제, **기말 = 오늘 실잔고**. daily 행에 `당일실적: True`, 시나리오 실행일 행은 계좌별 실잔고 값(숨기지 않음). **아직 안 나간 예정(확정입금 미도착·조정지출 포함)은 익일(다음 영업일)로 이월**되어 익일 행에 가산되고 비고에 이월 표시 — 그래서 **익일 기초 = 오늘 실잔고이고 자금 예산은 익일부터 시작**. 확인 단계의 '당일 지출·실제 차이' 행(처리: 기본 '지출 예정(유지)' / '보류(제외)')에서 보류한 항목의 잔여는 이월하지 않는다(load_intraday_holds → intraday_holds). 당일 대조의 자동 집행 판정은 **이름 근거(유사도 40 초과 — 정확히 40.0은 무관한 짧은 이름의 구조적 잡음이라 제외) 또는 강한 점수 근거(60점 이상, 이름 가점 문턱 45)**가 있을 때만 하고, 근거 없는 근사 금액·무관 출금은 계획에 흡수하지 않고 계획외 지출로 분리한다(2026-09-22 오귀속 수정 — 이미 나간 지출이 '미집행'으로 뜨면 확인 단계에서 '보류(제외)' 선택으로 이월을 막는다). 경영보고: 실행일 행은 실적 값(is_actual 스타일), 이월일 D 수식 = SUMIFS + 이월값.
6. **결과 = 통합 파일 1개**(05_결과, `주간자금계획_일시.xlsx` — 2026-09-23 사용자 요청, management_report.create_combined_workbook): 시트 순서(2026-09-23 v11 사용자 요청: 안내 시트 2개를 맨 앞으로) = ⓪ **요약**(라이브 요약 + 사용 방법 5줄을 통합 파일 기준으로 재작성(_rewrite_summary_usage) + 19행부터 '경영보고 시트 수정 방법 — 무엇을 고치면 어디가 바뀌나' 표(_fill_summary_guide): 반영률 F12·② 지급일/금액·G 실지출·I 적용/보류·③ 확정입금·목표잔액 각각의 수정법과 반영되는 시트·위치 6행 + 유의 문구) ⓪′ **업데이트운영**(_fill_update_guide로 매 실행 전면 재작성 — 옛 채팅 업로드 안내 삭제: ① 매주 운영 순서 6단계(은행 파일→팀 지출계획→자동 실행→확인·저장→수정·보고→금요일 대조) ② 이 파일의 시트 구성 11행 ③ 현재 반영된 은행 자료(bank_rows 은행별 건수·기간 자동 집계, 중복제외 행 제외); 스텁 템플릿에 시트가 없으면 생성) → ① **경영보고**(SHEET_NAME, 입력 기준. 실행일~차주 금요일만 표시, 노란 칸 수정 시 즉시 재계산. 섹션 순서(2026-09-23 사용자 요청: 지출표를 현황 바로 다음으로) = **①현황**(계좌 6~11 고정, 총잔액 12행, 반영률 F12) **②반영된 지출예정**(행 16~109+합계 110, F지급방법·G실지출·H차이·I확인 — 2026-09-23 v10: G는 **전 행 노란 수기 입력 칸**(당일 대조가 요청ID로 연결되면 은행 확인 집행액 프리필, 차이 행 FFE699), H는 전 행 `=IF(OR(G,E빈칸),"",E-G)` 차이 수식, I는 **적용/보류 드롭다운**(빈칸=적용) — **'보류' 행은 합계 E110·④ D열·라이브·대표보고 SUMIFS 조건 `"<>보류"`로 전부 제외**. 빈 예비 행(숨김, exp_next_row~109)에도 A/E/G 노란 칸·B 요일 수식·H 수식·I 드롭다운이 깔려 행 숨기기 해제로 지출 추가 가능. 필터 A15:I109) **③반영된 입금예정**(행 114~135+합계 136 — 일별 온라인 예상 = ④ 숨김 J열×반영률 수식·확정입금 항목(일자·금액 노란 칸, 창 밖 4주 확정입금은 숨김 행으로 포함)·실입금·차이) **④4주 일별 흐름**(행 140~167, 합계 168·판정 169 — D열은 ② SUMIFS(보류 제외), 숨김 도우미 J(요일평균)·K(확정입금 — 계획 행은 ③ SUMIFS, 이월일은 +이월확정 리터럴), 시작잔액 $K$139. 2026-09-23 v10: '상태' 열 대신 **'지출 내역' 열(F:I 병합)** — 그 날짜에 반영된 ② 항목을 "내용 금액 · …"로 나열하는 **배열 수식**(ArrayFormula로 저장한 IFERROR+TEXTJOIN+IF, 보류 제외·잔액 음수면 '⚠ 잔액 부족' 접두, TEXTJOIN 없는 구형 엑셀은 IFERROR 폴백으로 부족 표시만) — ②에서 지급일·금액을 고치면 나열도 따라온다. 실적 행은 "실적(은행 확인)", 이월일은 "전일 미집행 이월 포함 · " 접두) ⑤필요추가입금(목표 C172, 시나리오 174~176) ⑥메모(A180). ② **대표보고**(CEO_SHEET — PDF 대체, 경영보고 셀 참조 수식 한 장: 핵심 요약·금주 일별 전망·80/90/100% 시나리오, A4 세로 fitToWidth/Height=1 인쇄 설정) ③ **라이브 시트들**(fill_live_workbook(link_sheet='경영보고'): 요약 B13 = ='경영보고'!$F$12, 4주일별계획 계획 행의 확정·송금·카드·조정지출 = 경영보고 ③·④ SUMIFS(+이월 리터럴, 실적·당일실적 행은 값), 계좌별시나리오·13주(숨김)·요약은 기존 수식 체인으로 자동 연동. 실행일 전의 지난 실적 일자만 행 숨김, 지출계획_취합은 실행일~차주 금요일만 표시). 8. 날짜가 들어가는 모든 시트에서 주말·공휴일은 붉은 글자.
9. 이전 결과·확인 파일은 `99_지난자료`로 이동 후 14일 뒤 자동 삭제. 은행 파일은 계좌별 최신만 유지.
9-0. **내부이체(계좌간이체)는 키워드만으로 확정하지 않는다**(bank_classifier.mark_internal_transfers): 회사명 키워드는 '후보'일 뿐이고, 같은 거래일·같은 금액의 반대편 거래가 다른 우리 계좌에 실제로 있을 때만 짝으로 표시한다. 네이버 광고비 충전 가상계좌('국민네이버 apha/에이팜건' — 계좌명에 광고주명이 붙음)가 내부이체로 오분류되어 총 시작잔액이 계좌별 출발 합과 어긋났던 문제(2026-09-21, 2,508,000원)의 재발 방지. 매 실행 병합 이력 전체를 재판정하므로 과거 오표시·한 다리만 보이던 이체도 자동 복구된다.
9-1. **은행 파일은 확장자와 무관하게 내용으로 판별해 읽는다**(bank_loader `_read_raw_rows`): 매직바이트 스니핑으로 xlsx(zip)·구형 xls(OLE, xlrd)·HTML 표(.xls로 저장된 은행 다운로드)·CSV/TSV(utf-8-sig/cp949/utf-16, 탭·콤마 자동)를 모두 처리하고, 스타일 XML이 깨진 xlsx는 최소 스타일로 교체해 복구 시도, 서식이 사라져 날짜가 엑셀 일련값으로 오면 날짜로 되살린다. file_validator의 은행 파일 검사도 내용 기준(`_bank_file_readable`).
9-2. **더존(ERP) 내보내기도 은행 파일로 받는다**(2026-09-22 사용자 요청): 열 = 월/일·적요·입금액·출금액·잔액, 날짜는 연도 없는 '09-21' 형태(`_parse_month_day` — 기준일보다 일주일 넘게 미래면 지난해로 보정), '전일잔액' 행은 0원 잔액 기준행으로 유지하고 '합 계'(공백 포함) 행은 제외. 파일 안에 계좌번호가 없으므로 **파일명 숫자에서 계좌 힌트를 찾는다**(`_account_hint_from_filename` — YYYYMMDD·YYMMDD 날짜 토큰 제외, 공백은 계좌 구분자로 안 봄). `unify_account_labels`(load_all_banks 끝 + app의 이력 병합 직후)가 짧은 라벨을 같은 은행의 뒷자리 일치 전체 계좌번호(정확히 하나일 때)로 통일해 잔액 이중 합산·내부이체 오판을 막는다 — 같은 거래가 더존·은행 원본 양쪽에 있어도 중복 제거(은행+거래일+금액+잔액)로 한 번만 반영. 상대방 이름은 적요로 들어오며 매칭·분류는 적요+기재내용을 합쳐 보므로 그대로 동작. 잔액 열 없는 더존 보고서는 지원하지 않는다(문서에 안내).
10. **금요일 주간 대조**(weekly_reconcile.py): 금 17:00 자동(+트레이 메뉴, `--weekly-reconcile` CLI)으로 이번 주 계획 vs 실제 입출금을 계좌별 대조한 `주간대조_일시.xlsx`(안내·계좌별대조·차이내역)를 06_확인필요에 생성 — 미집행(FFE699)·계획없는출금(FFC7CE)·금액차이(FFF2CC)를 사용자에게 먼저 확인받는다. payment_matcher 재사용, 주초 잔액은 현재 잔액에서 주간 거래 되돌림(내부이체 포함).
