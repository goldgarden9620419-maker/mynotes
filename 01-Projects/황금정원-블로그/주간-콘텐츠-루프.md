# 황금정원 주간 콘텐츠 루프

> ⏸️ **2026-10-28 일시 중지** — 블로그 글쓰기와 티스토리 발행을 고정 세션의 「블로그+스레드 발행 스튜디오」에서 직접 경험을 넣어 진행하고 있어, 이 루프와 중복된다는 사용자 판단으로 월요일 예약 작업을 껐다. 루프 초안 2편 중 「아침형은 타고날까」는 스튜디오 목록에 남아 있고, 「주말 늦잠의 함정」은 스튜디오에서 삭제됨(원본 노트는 이 폴더에 있음). 다시 켜려면 예약 작업을 enabled로 바꾸면 된다.

`marketing-loops` 스킬 기반으로 설계한 반복 워크플로우. 매주 자동으로 실행되어 블로그 콘텐츠 초안을 채워두고, **최종 발행은 항상 사람이 확인**한다.

## 루프 명세

### The 황금정원 weekly content loop
- **Check cadence**: 매주 1회 (월요일 오전 9시 KST)
- **Acts when**: 대기 중(미발행) 초안 개수가 버퍼(2편) 미만일 때만 새 글을 만든다. 버퍼가 차 있으면 이번 주는 스킵.
- **Purpose**: 황금정원 블로그의 콘텐츠 파이프라인이 마르지 않게, 바로 쓸 수 있는 글감 카드(참고 영상·경험 질문 포함)를 항상 1~2개 확보해둔다.
- **Skills used**: `customer-research`
- **Loop body**:
  1. `.agents/loops/golden-garden-content.json`에서 `pending_drafts` 개수 확인
  2. `buffer_target`(2) 이상이면 스킵하고 종료
  3. 미달이면 (중복 체크 대상: `handled_topics` + `전체-발행-글-목록.md` + 발행 스튜디오의 `meta/history` 제목 목록 — 스튜디오에서 사용자가 직접 쓴 글도 여기 들어 있음) 먼저 `01-Projects/황금정원-블로그/다음-주제-후보.md`에서 미사용(체크 안 된) 항목이 있는지 확인해 있으면 그걸 사용한다. 없으면 `customer-research`로 새 주제 후보 1개 탐색 (4개 콘텐츠 축 — 새벽 루틴/확언·자기암시/부자의 습관/사주·운세 — 기준, `handled_topics`와 중복 없는 주제)
  4. **글감 카드만 만든다 (2026-10-26 사용자 결정 — 완성 글 작성 금지)**: 승인글은 사용자의 경험·생각을 받아 세션에서 함께 쓴다(`승인글-쓰는-방식.md`). 루프는 주제마다 ① 주제·가제 ② 대본(스크립트)이 나오는 한국어 유튜브 참고 영상 후보 1~2개(링크·채널명) ③ 경험 떠올리기 질문 2~3개 ④ 비판 쟁점 1개 ⑤ 근거 자료 링크 2개(직접 열어 확인한 것)를 정리한다.
  5. 이미지는 만들지 않는다(사진은 글 쓸 때 Pixabay에서 고른다).
  6. 글감 카드를 `01-Projects/황금정원-블로그/다음-주제-후보.md` 맨 위에 추가하고 git commit/PR (병합은 사용자 확인 후).
  7. `golden-garden-content.json`의 `handled_topics`·`pending_drafts`·`last_run` 갱신. `pending_drafts` 항목에 스튜디오 doc_id(`studio_doc`)도 적는다. 스튜디오에서 발행이 끝나면(문서의 `done` 6단계가 모두 true) 다음 실행 때 `published`로 옮긴다. 후보 목록에서 가져온 주제였다면 `다음-주제-후보.md`에서 해당 항목도 체크 표시
- **Self-check**: 새 주제가 4개 콘텐츠 축 중 하나에 속하는가? 기존 발행·대기 글과 주제가 겹치지 않는가? (겹치면 스킵하고 다음 주로 미룸, 억지로 만들지 않음)
- **State / idempotency**: `.agents/loops/golden-garden-content.json` — `handled_topics`(중복 방지), `pending_drafts`(버퍼 카운트), `last_run`(워터마크), `counters.consecutive_no_new_topic`
- **Stop / bail-out**:
  - 이미지 생성은 **1회 실행당 최대 1장, 약 2크레딧 이내**로 캡 — 이 상한을 넘는 요청(예: 여러 장, 영상 생성)은 자동 실행하지 않고 사람에게 확인
  - **티스토리 실제 발행, 브랜치 병합(PR merge)은 절대 자동으로 하지 않는다** — 항상 다음 대화에서 사람 확인 후 진행
  - 새 주제를 3회 연속(3주) 못 찾으면 루프를 스스로 비활성화하고 알림 (콘텐츠 축이 소진됐다는 신호)
  - 실행 중 오류가 나면 조용히 넘어가지 않고 다음 대화에서 오류를 보고
- **Output**: vault 노트 파일(본문+쓰레드+헤더이미지) + git PR + 사람에게 요약 알림

## 자동 vs 사람 확인 경계

| 단계 | 자동 실행 | 사람 확인 |
|---|---|---|
| 리서치·주제 선정 | ✅ | |
| 블로그 초안 작성 | ✅ | |
| 헤더 이미지 생성 (최대 1장) | ✅ | |
| vault 노트 저장 (git commit) | ✅ | |
| PR 병합 | | ✅ |
| 발행 스튜디오에 글 넣기 | ✅ | |
| 티스토리 실제 발행 | | ✅ (항상 사람이 직접, 스튜디오 세션에서) |

## 스케줄

Routine(예약 실행)으로 매주 월요일 오전 9시(KST)에 이 세션을 깨워 위 루프를 실행하도록 설정.
