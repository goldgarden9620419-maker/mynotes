# 황금정원 주간 콘텐츠 루프

`marketing-loops` 스킬 기반으로 설계한 반복 워크플로우. 매주 자동으로 실행되어 블로그 콘텐츠 초안을 채워두고, **최종 발행은 항상 사람이 확인**한다.

## 루프 명세

### The 황금정원 weekly content loop
- **Check cadence**: 매주 1회 (월요일 오전 9시 KST)
- **Acts when**: 대기 중(미발행) 초안 개수가 버퍼(2편) 미만일 때만 새 글을 만든다. 버퍼가 차 있으면 이번 주는 스킵.
- **Purpose**: 황금정원 블로그의 콘텐츠 파이프라인이 마르지 않게, 발행 준비된 초안을 항상 1~2편 확보해둔다.
- **Skills used**: `customer-research`, `copywriting`, `adsense-approval-post`, `image`
- **Loop body**:
  1. `.agents/loops/golden-garden-content.json`에서 `pending_drafts` 개수 확인
  2. `buffer_target`(2) 이상이면 스킵하고 종료
  3. 미달이면 `customer-research`로 새 주제 후보 1개 탐색 (4개 콘텐츠 축 — 새벽 루틴/확언·자기암시/부자의 습관/사주·운세 — 기준, `handled_topics`와 중복 없는 주제)
  4. `copywriting` + `adsense-approval-post`로 티스토리 카드형 HTML 초안 + 자문자답 FAQ + 쓰레드(반말) 버전 작성
  5. `image`로 헤더 이미지 **최대 1장** 생성 (실사 스타일, Nano Banana 계열, 예상 2크레딧 이내 — 사용자가 승인한 상한)
  6. `01-Projects/황금정원-블로그/`에 노트로 저장 → git commit/PR (병합은 이번에도 사용자 확인 후 진행)
  7. `golden-garden-content.json`의 `handled_topics`·`pending_drafts`·`last_run` 갱신
- **Self-check**: 새 주제가 4개 콘텐츠 축 중 하나에 속하는가? 기존 발행·대기 글과 주제가 겹치지 않는가? (겹치면 스킵하고 다음 주로 미룸, 억지로 만들지 않음)
- **State / idempotency**: `.agents/loops/golden-garden-content.json` — `handled_topics`(중복 방지), `pending_drafts`(버퍼 카운트), `last_run`(워터마크), `counters.consecutive_no_new_topic`
- **Stop / bail-out**:
  - 이미지 생성은 **1회 실행당 최대 1장, 약 2크레딧 이내**로 캡 — 이 상한을 넘는 요청(예: 여러 장, 영상 생성)은 자동 실행하지 않고 사람에게 확인
  - **티스토리 실제 발행, 브랜치 병합(PR merge)은 절대 자동으로 하지 않는다** — 항상 다음 대화에서 사람 확인 후 진행
  - 새 주제를 3회 연속(3주) 못 찾으면 루프를 스스로 비활성화하고 알림 (콘텐츠 축이 소진됐다는 신호)
  - 실행 중 오류가 나면 조용히 넘어가지 않고 다음 대화에서 오류를 보고
- **Output**: vault 노트 파일(본문+쓰레드+헤더이미지) + git PR + 사람에게 요약 알림

## 자동 vs 사람 확인 경계

| 단계 | 자동 실행 | 사람 확인 |
|---|---|---|
| 리서치·주제 선정 | ✅ | |
| 블로그 초안 작성 | ✅ | |
| 헤더 이미지 생성 (최대 1장) | ✅ | |
| vault 노트 저장 (git commit) | ✅ | |
| PR 병합 | | ✅ |
| 티스토리 실제 발행 | | ✅ (항상 사람이 직접) |

## 스케줄

Routine(예약 실행)으로 매주 월요일 오전 9시(KST)에 이 세션을 깨워 위 루프를 실행하도록 설정.
