# 광고영상 UGC 제작 워크플로우

Higgsfield MCP로 제품 광고영상(UGC 스타일)을 만드는 반복 가능한 표준 절차. 핵심 원칙은 **"한 번에 끝까지 만들지 않는다"** — 각 단계 결과물을 보여주고, 수정할 게 있는지 물어본 뒤 승인받아야 다음 단계로 넘어간다.

예외: 사용자가 특정 세션에서 "묻지말고 끝까지 진행해" 같은 명시적 포괄 승인을 준 경우에만 해당 작업 한정으로 단계별 확인을 생략한다. 그 외에는 항상 아래 체크포인트를 지킨다.

## 0. 시작 전 확인
`get_workflow_instructions()` (인자 없이) 호출해서 워크플로우 카탈로그 확인 → `ugc-flow` 관련 워크플로우 로드. 번들 파일이 필요하면 `get_workflow_bundle_file`로 불러온다.

## 단계별 진행 + 확인 체크포인트

### 1단계. 제품 정보 수집
- 제품명, 특징(성분/인증/차별점), 타겟 고객, 톤앤매너, 포맷(길이/비율/플랫폼), 구매 유도 방식(검색유도/링크/프로모션)을 질문으로 확인
- 제품 사진은 사용자에게 직접 업로드 요청 (`media_upload_widget`) — 쇼핑몰 URL 스크래핑은 봇 차단(403)으로 대부분 실패하니 처음부터 업로드 요청이 낫다
- ✋ **체크포인트 없음** (아직 결과물이 없으므로) — 바로 2단계로

### 2단계. 스크립트 초안
- Scene별 샷/대사/자막 구성한 스토리보드 스크립트 작성 (`monologue-craft.md` 참고)
- **✋ 사용자에게 스크립트 전체를 보여주고 "수정하실 부분 있으신가요?" 확인. 승인 후에만 3단계 진행.**

### 3단계. 캐릭터 생성
- `soul_2` 모델로 인물 캐릭터 시트 생성 (get_workflow_instructions({workflow:"character-sheet"}) 먼저 확인)
- 사용자가 구체적 외모 묘사를 주면 그대로 반영
- **✋ 생성된 캐릭터 이미지를 보여주고 "이 캐릭터로 진행할까요, 수정할까요?" 확인**

### 4단계. 제품 레퍼런스 이미지 정리
- 사용자가 올린 실물 사진이 지저분하거나 라벨 텍스트가 작으면, `nano_banana_pro`로 깔끔한 스튜디오 컷을 먼저 만든다 (텍스트/라벨 재현에 가장 강한 모델)
- 프롬프트에 브랜드명을 직접 타이핑하지 말 것 — 오타 위험. "레퍼런스 이미지에 적힌 문구를 그대로 복사(glyph-for-glyph copy)"라고 지시
- **✋ OCR 또는 육안으로 라벨 텍스트가 정확한지 확인 후 사용자에게 보여주고 승인받기**

### 5단계. 스토리보드 (8-slot 보드)
- `gpt_image_2`로 보드 생성 → `seedream_v5_pro`로 deslop(사실감 보정)
- 음료/섭취 장면 등에서 NSFW 오탐 발생 시: "wellness product demo, entirely non-suggestive, PG, fully clothed" 식으로 문구를 명시적으로 순화해서 재시도
- **✋ 보드 4개(HOOK/REVEAL/APPLY/CLOSER) 모두 보여주고 "이대로 클립 제작 진행할까요?" 확인**

### 6단계. 비디오 클립 생성
- `seedance_2_0`, 9:16, 15초 단위 클립 (대사/음성 네이티브 렌더링)
- 클립 스티칭까지 완료
- **✋ 스티치된 원본(자막 없는) 영상을 보여주고 확인 — 이 시점에 캐릭터/제품/동작 문제를 미리 잡는 게 자막 작업보다 수정 비용이 훨씬 낮다**

### 7단계. 자막 + CTA
- `transcribe_words.py --lang ko` (whisper) 로 타이밍 추출. 모델은 "tiny"로 빠르게 시도하되, 스크립트 원문(script.txt)과 단어 단위로 대조해서 **한 단어라도 안 맞는 자막 그룹은 통째로 버리는** 필터를 반드시 적용 (환각 방지)
- ASS 자막 스타일의 MarginV는 실제 영상 해상도 기준으로 재계산 (`round(0.15 * H)`), 1080 가정하지 말 것
- 마지막에 검색 유도 CTA 배너(drawtext) 삽입
- sandbox_exec는 60초 타임아웃 표시가 나도 서버 작업은 끝났을 수 있고, 세션 간 파일이 사라지는 경우가 잦다 → **다운로드~처리~업로드~검증(content-length 대조)을 한 번의 sandbox_exec 호출 안에서 전부 처리**하고, 재시도 시 media_upload 슬롯을 새로 발급받는다
- **✋ 최종 완성 영상(자막+CTA 포함)을 보여주고 "자막 타이밍, 제품 라벨, CTA 문구 다 괜찮으신가요?" 확인**

### 8단계. Obsidian 노트 기록
CLAUDE.md 규칙 그대로 적용:
- `00-Inbox/`에 노트 작성 (스크립트, 완성 영상 링크, 캡션/해시태그, 구매 링크 등)
- **✋ 노트 내용을 먼저 보여주고 git add+commit+push 진행해도 되는지 확인**
- 승인 후에만 커밋/푸시. 커밋 메시지는 내용 요약.

### 9단계. 게시 지원

**공통**
- Instagram Reels / TikTok용 캡션+해시태그를 별도로 작성 (플랫폼별 톤 차이 반영: Reels는 조금 더 정제된 톤, TikTok은 더 캐주얼)
- 프로필 구매 링크 등록도 요청 시 단계별 안내 (모바일 전용 기능일 수 있음 — 데스크톱에서 안 되면 모바일 앱 안내)

**TikTok — 자동 게시 가능 (연결 완료, 2026-08-08)**
- `tiktok_accounts`로 활성 계정의 `connector_id` 확인 (status가 "active"인지 먼저 체크, "error"면 `tiktok_reconnect` 안내)
- `tiktok_prepare_publish` → 캡션, 공개범위(privacy_level), AIGC 여부(is_aigc: true, AI 생성 영상이므로) 등을 담아 세션 생성
- **✋ prepare 결과(미리보기, 공개범위 옵션, 필수 동의 항목)를 사용자에게 보여주고 최종 확정받기** — 특히 공개범위(전체공개/나만 등)는 반드시 사용자가 명시적으로 선택하게 할 것
- 승인받은 값 그대로 `tiktok_publish` 호출 (필수 confirmation 플래그 전부 true로)
- `tiktok_publish_status`로 처리 결과 확인 후 사용자에게 완료 보고
- 계정이 없거나 error 상태면 `tiktok_connect`로 재연결 안내 (인증 링크는 ~10분 내 만료)

**Instagram — 자동 게시 불가 (커넥터 없음, 2026-08-08 기준)**
- 이 환경에는 Instagram/Meta 자동 게시 MCP 커넥터가 없음 (ListConnectors/SearchMcpRegistry로 확인됨, Meta Business API 앱 심사 필요해 도구 범위 밖)
- 매번 새 영상마다 커넥터 존재 여부를 다시 확인할 필요는 없음 — 이미 확인된 사실이므로 곧바로 수동 안내로 진행
- 영상 다운로드 → Instagram Studio/앱에서 업로드 → 캡션 붙여넣기 → 게시까지, 사용자가 보내는 화면 스크린샷을 기준으로 그때그때 다음 클릭 지점을 짚어주는 방식으로 안내
- **✋ 캡션/해시태그 최종본을 보여주고 확인받은 뒤 업로드 안내 시작**

## 핵심 원칙 요약
1. 8단계 전 과정에서 최소 7번의 확인 체크포인트를 거친다 (2~9단계 각각)
2. 사용자가 명시적으로 "묻지말고 끝까지 해줘"라고 하지 않는 한 절대 건너뛰지 않는다
3. 수정 요청이 오면 해당 단계로 돌아가 다시 만들고, 그 이후 단계부터 재실행한다 (전체를 처음부터 다시 만들 필요는 없음)
4. 노트/게시물처럼 외부에 남는 산출물은 항상 "보여주기 → 확인 → 실행" 순서를 지킨다
