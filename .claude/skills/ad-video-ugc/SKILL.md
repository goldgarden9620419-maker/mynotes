# 광고영상 UGC 제작 워크플로우

Higgsfield MCP로 제품 광고영상(UGC 스타일)을 만드는 반복 가능한 표준 절차. 핵심 원칙은 **"한 번에 끝까지 만들지 않는다"** — 각 단계 결과물을 보여주고, 수정할 게 있는지 물어본 뒤 승인받아야 다음 단계로 넘어간다.

큰 흐름: **스토리보드(씬 구성) → 이미지 생성(캐릭터+제품+씬별 보드) → 영상 생성(씬별 클립) → 하나의 씬으로 합치기(스티칭+자막+CTA) → 노트 기록 → 게시**

예외: 사용자가 특정 세션에서 "묻지말고 끝까지 진행해" 같은 명시적 포괄 승인을 준 경우에만 해당 작업 한정으로 단계별 확인을 생략한다. 그 외에는 항상 아래 체크포인트를 지킨다.

## 0. 시작 전 확인
`get_workflow_instructions()` (인자 없이) 호출해서 워크플로우 카탈로그 확인 → `ugc-flow` 관련 워크플로우 로드. 번들 파일이 필요하면 `get_workflow_bundle_file`로 불러온다.

## 단계별 진행 + 확인 체크포인트

### 1단계. 제품 정보 수집
- 제품명, 특징(성분/인증/차별점), 타겟 고객, 톤앤매너, 포맷(길이/비율/플랫폼), 구매 유도 방식(검색유도/링크/프로모션)을 질문으로 확인
- 제품 사진은 사용자에게 직접 업로드 요청 (`media_upload_widget`) — 쇼핑몰 URL 스크래핑은 봇 차단(403)으로 대부분 실패하니 처음부터 업로드 요청이 낫다
- ✋ **체크포인트 없음** (아직 결과물이 없으므로) — 바로 2단계로

### 2단계. 스토리보드 작성 (씬 구성)
- Scene별 샷/대사/자막을 텍스트로 구성 (`monologue-craft.md` 참고). 이 시점에는 이미지/영상 없이 글로만 정리
- 보통 HOOK → REVEAL → APPLY → CLOSER 4개 씬 구조
- **✋ 사용자에게 스토리보드 전체를 보여주고 "수정하실 부분 있으신가요?" 확인. 승인 후에만 3단계 진행.**

### 3단계. 이미지 생성 (스토리보드에 맞춰)
스토리보드에서 정한 씬 구성에 맞는 비주얼 자료를 준비하는 단계. 아래 세 가지를 순서대로 만든다.

**3-1. 캐릭터 시트**
- `soul_2` 모델로 인물 캐릭터 생성 (`get_workflow_instructions({workflow:"character-sheet"})` 먼저 확인)
- 사용자가 구체적 외모 묘사를 주면 그대로 반영

**3-2. 제품 레퍼런스 이미지 정리**
- 사용자가 올린 실물 사진이 지저분하거나 라벨 텍스트가 작으면, `nano_banana_pro`로 깔끔한 스튜디오 컷을 먼저 만든다 (텍스트/라벨 재현에 가장 강한 모델)
- 프롬프트에 브랜드명을 직접 타이핑하지 말 것 — 오타 위험. "레퍼런스 이미지에 적힌 문구를 그대로 복사(glyph-for-glyph copy)"라고 지시
- OCR 또는 육안으로 라벨 텍스트가 정확한지 먼저 확인

**3-3. 씬별 보드 이미지 (8-slot)**
- 캐릭터 + 제품 레퍼런스를 반영해서 `gpt_image_2`로 씬별 보드 생성 → `seedream_v5_pro`로 deslop(사실감 보정)
- 음료/섭취 장면 등에서 NSFW 오탐 발생 시: "wellness product demo, entirely non-suggestive, PG, fully clothed" 식으로 문구를 명시적으로 순화해서 재시도

- **✋ 캐릭터, 제품 레퍼런스, 씬별 보드 이미지(HOOK/REVEAL/APPLY/CLOSER)를 모두 보여주고 "이 이미지들로 영상 제작 진행할까요?" 확인. 승인 후에만 4단계 진행.**

### 4단계. 영상 생성 (씬별 클립)
- 3단계에서 승인받은 보드 이미지를 기반으로 `seedance_2_0`, 9:16, 씬당 15초 단위로 클립 생성
- 씬별로 개별 클립만 생성하고, 아직 하나로 합치지 않음
- ⚠️ **클립 프롬프트에 시각 묘사만 넣고 실제 대사(한국어 스크립트)를 넣지 않으면, 모델이 자체적으로 지어낸 엉뚱한 오디오("구독, 좋아요" 같은 문구)를 렌더링하는 경우가 있다.** 클립 생성 전에 씬별 대사를 정해뒀다면 프롬프트에 명시적으로 포함시키고, 이미 클립을 생성했다면 5단계로 넘어가기 전에 네이티브 오디오에 실제 대사가 들어있는지 반드시 확인한다 (클립 하나를 다운로드해서 오디오만 추출 후 짧게 들어보거나 whisper로 빠르게 확인)
- ⚠️ **제품이 클로즈업/매크로 컷에서 화면 밖으로 잘려 안 보이는 경우가 있다** (예: 우산이 펼쳐지는 순간 손잡이만 보이고 캐노피는 프레임 밖). 특히 자동 작동/개폐 같은 핵심 기능 컷에서는 프롬프트에 "camera pulled back enough to keep the full [product] visible in frame", "never crop [핵심 부품] out of frame" 같은 프레이밍 지시를 명시적으로 넣는다
- **✋ 씬별 클립을 각각 보여주고 "이대로 하나의 영상으로 합칠까요?" 확인 — 이 시점에 캐릭터/제품/동작 문제를 미리 잡는 게 다음 단계보다 수정 비용이 훨씬 낮다**

### 5단계. 하나의 씬으로 합치기 (최종 영상)
- 승인된 클립들을 순서대로 스티칭해서 하나의 영상으로 합침
- **오디오 트랙 확인**: 4단계에서 클립 네이티브 오디오에 실제 대사가 안 들어있는 게 확인됐다면(또는 애초에 클립 프롬프트에 대사를 안 넣었다면), 클립의 원본 오디오는 버리고(`-an`) 별도 한국어 TTS로 대체한다.
  - `generate_audio_batch`로 씬별 대사를 TTS 생성 (모델 `inworld_text_to_speech`, 한국어 보이스 `Hyunwoo`/`Minji`/`Seojun`/`Yoona` 중 선택). 씬 순서대로 index 매겨서 한 번에 요청
  - 각 TTS 오디오를 해당 씬 블록 길이(예: 15초)에 맞춰 무음 패딩(`apad` + `-t`)한 뒤 이어붙여 전체 내레이션 트랙 생성, 영상(오디오 제거된 클립들을 concat한 것)과 믹스
  - **이 경우 자막은 whisper로 추출하지 않는다** — 이미 정확한 원본 스크립트 텍스트를 알고 있으므로, 각 TTS 오디오의 실제 길이(ffprobe)만 구해서 "씬 시작 시각 ~ 씬 시작 시각+TTS 길이" 구간에 원본 스크립트 문장을 그대로 자막으로 얹는다. whisper 오인식/환각 문제를 원천적으로 피하는 방법
  - 클립 네이티브 오디오에 실제로 정확한 대사가 들어있는 경우에만 아래의 whisper 경로를 쓴다: `transcribe_words.py --lang ko` (whisper)로 자막 타이밍 추출. 모델은 "tiny"로 빠르게 시도하되, 스크립트 원문(script.txt)과 단어 단위로 대조해서 **한 단어라도 안 맞는 자막 그룹은 통째로 버리는** 필터를 반드시 적용 (환각 방지). 그래도 부정확하면 whisper의 타이밍만 재사용하고 텍스트는 원본 스크립트로 수동 교체
- 폰트: 새 sandbox에는 한글 폰트(NanumGothic 등)가 기본 설치되어 있지 않을 수 있음 — `fc-list | grep -i nanum`으로 먼저 확인하고, 없으면 `https://raw.githubusercontent.com/google/fonts/main/ofl/nanumgothic/NanumGothic-Regular.ttf` (+ `-Bold.ttf`)를 받아 `~/.fonts`에 넣고 `fc-cache -f`
- ASS 자막 스타일의 MarginV는 실제 영상 해상도 기준으로 재계산 (`round(0.15 * H)`), 1080 가정하지 말 것
- 마지막에 검색 유도 CTA 배너(drawtext) 삽입 — 자막이 끝나는 시점과 겹치지 않게 타이밍 조정
- sandbox_exec는 60초 타임아웃 표시가 나도 서버 작업은 끝났을 수 있고, 세션 간 파일이 사라지는 경우가 잦다 → **다운로드~처리~업로드~검증(content-length 대조)을 한 번의 sandbox_exec 호출 안에서 전부 처리**하고, 재시도 시 media_upload 슬롯을 새로 발급받는다
- **✋ 최종 완성 영상(자막+CTA 포함, 하나로 합쳐진 상태)을 보여주고 "자막 타이밍, 제품 라벨, CTA 문구, 씬 전환 다 괜찮으신가요?" 확인**

### 6단계. Obsidian 노트 기록
CLAUDE.md 규칙 그대로 적용:
- `00-Inbox/`에 노트 작성 (스토리보드, 완성 영상 링크, 캡션/해시태그, 구매 링크 등)
- **✋ 노트 내용을 먼저 보여주고 git add+commit+push 진행해도 되는지 확인**
- 승인 후에만 커밋/푸시. 커밋 메시지는 내용 요약.

### 7단계. 게시 지원

수익화가 목적인 캠페인(쿠팡파트너스 등 제휴링크형)이면 **아래 순서를 반드시 지킨다** — 제휴링크가 없으면 영상을 아무리 올려도 수익 추적이 안 됨:

**7-0. 제휴링크 생성 (가장 먼저)**
- partners.coupang.com → "링크 생성" → 상품 URL 검색 → 채널 아이디 선택 후 링크 생성 (채널 아이디는 최초 1회만 만들면 됨, 이후 캠페인마다 재사용 — 보통 플랫폼별로 `tiktokchannel`/`instagramchannel` 등 하나씩)
- 쿠팡 상품 페이지는 봇 차단으로 직접 스크래핑 불가 — 가격/재고 확인은 사용자가 직접 캡처해서 알려주는 방식으로 진행
- 생성된 제휴링크를 노트 파일과 이후 캡션에 반영 (원본 URL이 아니라 반드시 이 링크를 사용해야 정산됨)

**7-1. Instagram Reels / TikTok용 캡션+해시태그 작성**
- 플랫폼별 톤 차이 반영 (Reels는 조금 더 정제된 톤, TikTok은 더 캐주얼)
- 캡션에 "쿠팡 파트너스 활동의 일환으로 수수료를 제공받습니다" 표시 문구 필수 포함 (공정위 가이드라인)

**7-2. TikTok — 자동 게시 (연결 완료, 2026-08-08)**
- `tiktok_accounts`로 활성 계정의 `connector_id` 확인 (status가 "active"인지 먼저 체크, "error"면 `tiktok_reconnect` 안내)
- `tiktok_prepare_publish` → 캡션, 공개범위(privacy_level), AIGC 여부(is_aigc: true, AI 생성 영상이므로) 등을 담아 세션 생성
- **✋ prepare 결과(미리보기, 공개범위 옵션, 필수 동의 항목)를 사용자에게 보여주고 최종 확정받기** — 특히 공개범위(전체공개/나만 등)는 반드시 사용자가 명시적으로 선택하게 할 것. 이전 캠페인과 같은 설정(전체공개/댓글 허용/듀엣·스티치 차단/음악 없음/Paid partnership)을 재사용할지 먼저 물어보면 빠름
- 승인받은 값 그대로 `tiktok_publish` 호출 (필수 confirmation 플래그 전부 true로)
- `tiktok_publish_status`로 처리 결과 확인 후 사용자에게 완료 보고
- 계정이 없거나 error 상태면 `tiktok_connect`로 재연결 안내 (인증 링크는 ~10분 내 만료)

**7-3. Instagram — 수동 게시 (자동 게시 커넥터 없음, 2026-08-08 기준)**
- 이 환경에는 Instagram/Meta 자동 게시 MCP 커넥터가 없음 (ListConnectors/SearchMcpRegistry로 확인됨, Meta Business API 앱 심사 필요해 도구 범위 밖) — 매번 재확인할 필요 없음
- 영상 다운로드(브라우저로 hosted URL 열어서 저장) → Instagram 웹/앱에서 업로드 → 캡션 붙여넣기 → **"AI 레이블 추가" 토글 켜기**(AI 생성 콘텐츠 표시 필수) → 게시까지, 사용자가 보내는 화면 스크린샷을 기준으로 그때그때 다음 클릭 지점을 짚어주는 방식으로 안내
- **✋ 캡션/해시태그 최종본을 보여주고 확인받은 뒤 업로드 안내 시작**

**7-4. 프로필 링크 관리 — 링크허브(Linktree) 방식 (최초 1회 설정, 이후 캠페인은 유지보수만)**
- 제품이 바뀔 때마다 Instagram/TikTok 프로필 링크를 직접 수정하는 대신, **Linktree 같은 링크허브 서비스 하나로 통합 관리**하는 게 반복 캠페인에 훨씬 효율적 (프로필은 최초 1회만 링크허브 주소로 등록해두면 끝)
- 최초 설정: linktr.ee 가입(무료 플랜으로 충분, 유료 체험판 팝업은 건너뛰기) → 목적 "창조자" 선택 → 소셜 계정 연결 → 상품 링크 추가 → Instagram/TikTok 프로필 웹사이트란에 `linktr.ee/유저명` 등록
  - TikTok은 일반 계정에서 웹사이트 링크 기능이 없을 수 있음 — 정식 비즈니스 인증(서류 필요)까지는 과함, 대신 **자기소개(바이오)에 텍스트로 링크 주소만 적어두는 것**으로 충분 (클릭은 안 되지만 시청자가 직접 검색 가능)
- 신규 캠페인마다 할 일: Linktree 대시보드 → "+ Add" → "Link" → 제휴링크 URL 붙여넣기 → 제목을 상품명으로 직접 수정(자동 미리보기가 "Sorry! Access denied"로 뜨는 건 쿠팡 페이지 메타데이터를 못 가져와서 생기는 표시 오류일 뿐, 링크 자체는 정상 작동 — 제목만 고치면 됨) → 저장
- **✋ 별도 확인 체크포인트 불필요** — 이미 승인된 제휴링크를 추가하는 기계적 작업이므로, 진행 상황만 보고

## 핵심 원칙 요약
1. 전 과정에서 최소 6번의 확인 체크포인트를 거친다 (2~7단계 각각)
2. 사용자가 명시적으로 "묻지말고 끝까지 해줘"라고 하지 않는 한 절대 건너뛰지 않는다
3. 수정 요청이 오면 해당 단계로 돌아가 다시 만들고, 그 이후 단계부터 재실행한다 (전체를 처음부터 다시 만들 필요는 없음)
4. 노트/게시물처럼 외부에 남는 산출물은 항상 "보여주기 → 확인 → 실행" 순서를 지킨다
5. 큰 흐름 순서를 지킨다: 스토리보드(글) → 이미지(캐릭터+제품+보드) → 영상(씬별 클립) → 합치기(스티칭+자막+CTA) → 노트 → 게시. 이미지/영상 준비가 안 된 상태에서 스토리보드 단계를 건너뛰지 않는다.
