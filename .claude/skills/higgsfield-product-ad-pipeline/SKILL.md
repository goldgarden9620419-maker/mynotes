# Higgsfield 제품 광고 이미지·영상 제작 파이프라인

실제 제품 사진의 디자인(라벨·컬러·형태)을 그대로 유지하면서, 힉스필드로 광고를 만드는 전체 워크플로우. 실제 광고 제작 순서(스토리보드 → 씬 촬영 → 편집)를 따른다 — 전체 그림을 먼저 확정하고 나서 씬 단위로 내려가야, 나중에 "박스가 안 나왔네" 같은 문제를 사전에 막을 수 있고 씬 하나가 마음에 안 들 때 그 씬만 다시 만들 수 있다.

## 전체 흐름

```
제품 사진 업로드(위젯) → [1] 스토리보드 설계·생성 → [2] 씬별 키비주얼 이미지 생성
→ [3] 씬별 영상 생성(start_image) → [4] 최종 조립(편집앱 또는 멀티샷 단일 생성)
```

## 0. 제품 사진 받기 — 반드시 업로드 위젯 사용

채팅에 첨부된 이미지는 힉스필드 원격 도구가 읽을 수 없다. 사용자가 채팅에 사진을 올렸더라도 `media_upload_widget`을 띄워 다시 올리게 해야 한다 (이유를 짧게 설명하고 "이번이 마지막"임을 안내하면 마찰이 줄어든다). 위젯이 돌려주는 `media_id`를 이후 모든 생성 호출의 참조로 사용한다. 한 번 받은 media_id는 세션 내내 재사용 가능하므로 다시 요구하지 말 것.

- 사용자가 "올렸다"고 하는데 media_id가 안 넘어왔으면(위젯 확인 버튼을 안 누른 경우) `show_medias`로 최근 업로드를 조회해 타임스탬프로 찾으면 된다.
- **깨진 업로드 주의**: 생성 요청이 "Something went wrong"으로 반복 실패하면 media 중 하나가 업로드 도중 끊긴 것일 수 있다 (목록에는 보이지만 실제 파일이 없음). 각 media의 URL을 `media_import_url`로 재등록해보면 판별된다 — 깨진 파일은 403으로 실패하고, 정상 파일은 새 media_id로 살아난다. 정상인 것만으로 진행하고 사용자에게 알린다.

## 1. 스토리보드 설계·생성 — 항상 여기서 시작

씬을 하나씩 즉흥적으로 만들지 말고, 광고 전체의 씬 구성을 먼저 확정한다.

**씬 구성 확정**: 몇 개의 씬으로 만들지, 각 씬이 무엇을 보여줄지(예: 씬1 매크로 훅 → 씬2 실루엣 공개 → 씬3 클라이맥스 → 씬4 제품 히어로), 컬러/조명이 씬을 거치며 어떻게 전개되는지(예: 암흑→빛) 큰 그림을 먼저 정한다. 사용자가 AD STUDIO 프롬프트나 구체적 지시를 줬으면 그걸 기반으로, 없으면 브리프(제품 특성·무드)에 맞춰 제안한다.

**제품 구성 확인**: 제품 사진에 박스·용기·낱개(캡슐/스틱 등)가 함께 있으면 어떤 씬에서 무엇을 주인공으로 할지 정한다. 낱개만 계속 등장시키면 박스가 광고에 한 번도 안 나오는 일이 생긴다 — 마지막 씬은 패키지 히어로 엔드카드로 두는 게 광고 관례상 자연스럽다.

**스토리보드 이미지 생성**: 확정한 씬 구성을 하나의 세로 캔버스에 수직 N분할(또는 그리드) 패널로 배치한 스토리보드 이미지를 나노바나나로 생성한다. 프롬프트에 반드시 포함:
- 패널 수·배치(예: "수직 5분할, 위에서 아래 순서")
- 각 패널이 담을 장면을 하나씩 구체적으로 서술 (구도·조명·주인공)
- "모든 Scene에서 동일 제품·배경·조명·디자인 아이덴티티 유지"
- 라벨 보존 규칙 (아래 2번 참고) — 스토리보드 단계부터 적용해야 이후 씬들이 어긋나지 않는다

이 스토리보드가 이후 모든 씬 이미지·영상의 기준(레퍼런스)이 된다. 사용자에게 보여주고 컨펌받은 뒤 다음 단계로 넘어간다.

## 2. 씬별 키비주얼 이미지 생성

컨펌된 스토리보드를 기준으로, 각 씬을 독립된 풀사이즈 이미지로 하나씩 생성한다. 모델은 이 단계도 `nano_banana_pro`(라벨 재현 가장 정확, 기본 1K, 확정본은 업스케일) 또는 `gpt_image_2`(2K/4K 직접 출력, 사용자가 명시할 때).

- `medias`에 **스토리보드 이미지(job_id)와 원본 제품 사진(media_id)을 함께** `role: "image"`로 전달 — 스토리보드의 해당 패널 구도·조명을 그대로 이어받되, 이번엔 그 한 장면만 프레임 가득 채운 고해상도 컷으로 만든다는 걸 프롬프트에 명시한다 ("스토리보드의 N번째 패널(씬 N)을 단독 고해상도 이미지로 확장").
- 씬마다 이전 씬과의 연속성(조명 전환, 파티클 밀도 변화 등)을 프롬프트에 챙겨 넣어야 나중에 영상으로 이었을 때 자연스럽다.

### ⚠️ 핵심: 텍스트 금지 조항과 라벨 보존의 충돌 해결

AD STUDIO 프롬프트에는 "한글, 영어, 텍스트를 절대 생성하지 말 것" 조항이 붙는데, 제품 라벨 자체가 한글이면 모델이 이 지시를 따르느라 **라벨을 뭉개거나 다르게 그린다**. 프롬프트를 그대로 쓰지 말고 반드시 이렇게 재구성한다:

1. 프롬프트 맨 앞에 라벨 보존을 최우선 지시로 배치: "박스 라벨의 모든 인쇄 문구(제품명 등 한글·영문 타이포그래피), 일러스트, 스탬프, 인증 마크, 컬러, 비율과 레이아웃을 원본 사진과 똑같이 재현할 것"
2. 금지 조항은 이렇게 수정: "제품 라벨의 기존 인쇄 문구는 원본 그대로 유지하되, 화면에 **새로운** 한글, 영어, 자막, 로고, 워터마크, UI, 텍스트를 절대 추가 생성하지 말 것"

**업스케일**: 확정 이미지는 `upscale_image`로 4K 업스케일. 원본의 `width`/`height`를 반드시 전달해야 한다 (job_display 결과의 params에서 확인 가능. 나노바나나 9:16 기본은 768×1376).

## 3. 씬별 영상 생성 — Seedance 2.0

씬 이미지가 확정되는 대로 그 씬의 영상을 만든다 (이미지 승인 → 즉시 영상, 씬 단위로 반복).

- 모델: `seedance_2_0`, `mode: "std"`, `resolution: "1080p"`, `generate_audio: false` (광고는 보통 후반에 음악을 따로 입힘 — 사용자가 오디오를 원하면 true)
- 확정 이미지를 `role: "start_image"`로 전달, 비율은 이미지와 동일하게(대개 9:16), duration은 프롬프트의 씬 길이에 맞춤(초 단위, 4~15)
- 사용자가 준 영상 프롬프트의 텍스트 금지 조항도 2번과 같은 방식으로 라벨 보존형으로 수정
- 이전 씬 영상의 마지막 프레임(또는 그 씬 이미지)과 이번 씬이 어떻게 이어지는지(매치컷/조명 전환 등)를 프롬프트 도입부에 한 문장 넣으면 씬 간 연결이 자연스러워진다

## 4. 최종 조립 — 하나의 광고로 합치기

씬 영상이 모두 완성되면 두 가지 방법 중 사용자 목적에 맞게 안내한다:

**A. 편집 앱으로 합치기 (기본 권장)** — 씬 영상 파일들을 순서대로 다운받아 캡컷 등에서 이어붙인다. 컷 타이밍·배경음악·자막을 세밀하게 제어할 수 있어 정식 송출용에 적합. 씬별로 개별 생성했으므로 이 경로가 자연스럽게 이어진다.

**B. 멀티샷 단일 생성 (빠른 시안용)** — 편집 없이 힉스필드에서 한 번에 이어진 영상을 뽑고 싶을 때. 씬 수 5개 이하·총 15초 이내가 안정적이다. `seedance_2_0`에 **스토리보드 이미지(job_id)와 원본 제품 사진을 둘 다 `role: "image_references"`**로 전달 (start_image가 아님 — 스토리보드는 첫 프레임이 아니라 참조 자료다). 프롬프트 필수 요소:
- 스토리보드가 총 N개의 Scene(패널)로 구성됨을 명시 — **N은 실제 패널 수와 반드시 일치시킬 것** (사용자가 붙여넣은 템플릿의 숫자가 실제와 다르면 고쳐서 사용)
- 각 패널을 독립된 장면으로 인식, Scene 1 → Scene N 순서 진행, 다른 패널 내용이 섞이거나 동시에 보이지 않게
- 장면 전환 방식(매치컷/조명 전환 등)과 씬별 카메라 무브 명시 (2·3단계에서 이미 정한 연출을 그대로 옮기면 됨)
- "업로드된 멀티샷 이미지를 시작 프레임으로 사용하여" 같은 표현은 절대 넣지 말 것
- duration = 씬 수 × 씬당 초 (예: 5씬 × 3초 = 15초)

두 방법 다 만들어줄 수도 있다 — B로 빠른 시안을 먼저 보여주고, 마음에 들면 A로 고품질 최종본을 만드는 흐름도 자연스럽다.

## 5. 진행 확인과 결과 표시

- 생성 시작 후 사용자에게 모델/설정 요약을 알리고, 확인 요청이 오면 `jobs_wait`(15초 롱폴)로 상태 확인. 이미지는 1~2분, 영상은 3~5분(15초짜리는 5분 이상) 걸린다고 안내.
- 완료되면 `job_display`로 결과 위젯 표시 + 결과 URL(rawUrl)을 함께 텍스트로 제공.

## 6. 다운로드 안내

실행 환경의 네트워크 정책이 힉스필드 CDN(cloudfront.net) 접근을 차단하는 경우가 있어 파일을 직접 받아 보내줄 수 없다. curl로 재시도하지 말고, 결과 URL을 주면서 "브라우저에서 열어 우클릭 → 저장" 또는 위젯의 다운로드 버튼을 안내한다.

## 7. AD STUDIO 앱과의 연계

이 vault의 `01-Projects/adstudio-local/`에는 브리프 → 씬별 스토리보드/이미지/영상 프롬프트(한글·영문)를 생성하는 로컬 Vite 앱(AD STUDIO)이 있다. 사용자는 보통 이 앱에서 프롬프트를 만들어 붙여넣는다. AD STUDIO의 "멀티샷 STEP 1(합성 이미지 프롬프트)"이 곧 이 스킬의 1단계 스토리보드에 해당하므로, 사용자가 그 프롬프트를 주면 그대로 1단계에 사용하면 된다. 프롬프트가 미완성(문장이 중간에 끊김)이거나 패널 수 등이 실제와 안 맞으면, 앞뒤 맥락으로 자연스럽게 보완·수정한 뒤 사용하고 무엇을 고쳤는지 사용자에게 알린다.
