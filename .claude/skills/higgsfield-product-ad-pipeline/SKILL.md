# Higgsfield 제품 광고 이미지·영상 제작 파이프라인

실제 제품 사진의 디자인(라벨·컬러·형태)을 그대로 유지하면서, 힉스필드로 광고 키비주얼 이미지를 만들고 그 이미지를 Seedance 2.0 광고 영상으로 발전시키는 전체 워크플로우.

## 전체 흐름

```
제품 사진 업로드(위젯) → 이미지 생성(나노바나나 기본) → [마음에 들면] 4K 업스케일
→ 단일 씬 영상(start_image) 또는 멀티샷 스토리보드 → 멀티샷 영상(image_references)
```

## 1. 제품 사진 받기 — 반드시 업로드 위젯 사용

채팅에 첨부된 이미지는 힉스필드 원격 도구가 읽을 수 없다. 사용자가 채팅에 사진을 올렸더라도 `media_upload_widget`을 띄워 다시 올리게 해야 한다 (이유를 짧게 설명하고 "이번이 마지막"임을 안내하면 마찰이 줄어든다). 위젯이 돌려주는 `media_id`를 이후 모든 생성 호출의 참조로 사용한다. 한 번 받은 media_id는 세션 내내 재사용 가능하므로 다시 요구하지 말 것.

## 2. 이미지 생성 — 모델 선택과 라벨 보존 규칙

- **기본 모델: `nano_banana_pro`** — 한글 라벨·패키지 디테일 재현이 가장 정확했다. 단 기본 해상도가 1K이므로 확정본은 업스케일 필요.
- 대안: `gpt_image_2` (2K/4K 직접 출력, quality: high) — 라벨 왜곡이 상대적으로 잦다. 사용자가 명시적으로 지정할 때 사용.
- 항상 `medias`에 제품 사진 media_id들을 `role: "image"`로 전달.

### ⚠️ 핵심: 텍스트 금지 조항과 라벨 보존의 충돌 해결

AD STUDIO 프롬프트에는 "한글, 영어, 텍스트를 절대 생성하지 말 것" 조항이 붙는데, 제품 라벨 자체가 한글이면 모델이 이 지시를 따르느라 **라벨을 뭉개거나 다르게 그린다**. 프롬프트를 그대로 쓰지 말고 반드시 이렇게 재구성한다:

1. 프롬프트 맨 앞에 라벨 보존을 최우선 지시로 배치: "박스 라벨의 모든 인쇄 문구(제품명 등 한글·영문 타이포그래피), 일러스트, 스탬프, 인증 마크, 컬러, 비율과 레이아웃을 원본 사진과 똑같이 재현할 것"
2. 금지 조항은 이렇게 수정: "제품 라벨의 기존 인쇄 문구는 원본 그대로 유지하되, 화면에 **새로운** 한글, 영어, 자막, 로고, 워터마크, UI, 텍스트를 절대 추가 생성하지 말 것"

## 3. 업스케일

사용자가 이미지를 확정하면 `upscale_image`로 4K 업스케일. 원본의 `width`/`height`를 반드시 전달해야 한다 (job_display 결과의 params에서 확인 가능. 나노바나나 9:16 기본은 768×1376).

## 4. 단일 씬 영상 — Seedance 2.0

- 모델: `seedance_2_0`, `mode: "std"`, `resolution: "1080p"`, `generate_audio: false` (광고는 보통 후반에 음악을 따로 입힘 — 사용자가 오디오를 원하면 true)
- 확정 이미지를 `role: "start_image"`로 전달, 비율은 이미지와 동일하게(대개 9:16), duration은 프롬프트의 씬 길이에 맞춤(초 단위, 4~15)
- 사용자가 준 영상 프롬프트의 텍스트 금지 조항도 2번과 같은 방식으로 라벨 보존형으로 수정

## 5. 멀티샷 (스토리보드 → 영상)

**STEP 1 — 스토리보드 합성 이미지**: 여러 씬을 한 캔버스에 상하/그리드 패널로 배치한 이미지를 나노바나나로 생성. 프롬프트에 패널 수·배치(예: 상하 2분할)와 "모든 Scene에서 동일 제품·배경·조명·디자인 일관성 유지"를 명시하고, 제품 사진 media_id를 참조로 전달.

**STEP 2 — 멀티샷 영상**: `seedance_2_0`에 스토리보드 이미지(job_id)와 원본 제품 사진을 **둘 다 `role: "image_references"`**로 전달 (start_image가 아님 — 스토리보드는 첫 프레임이 아니라 참조 자료다). 프롬프트 필수 요소:
- 스토리보드가 총 N개의 Scene(패널)로 구성됨을 명시 — **N은 실제 패널 수와 반드시 일치시킬 것** (사용자가 붙여넣은 템플릿의 숫자가 실제와 다르면 고쳐서 사용)
- 각 패널을 독립된 장면으로 인식, Scene 1 → Scene N 순서 진행, 다른 패널 내용이 섞이거나 동시에 보이지 않게
- 장면 전환 방식(매치컷/조명 전환 등)과 씬별 카메라 무브 명시
- "업로드된 멀티샷 이미지를 시작 프레임으로 사용하여" 같은 표현은 절대 넣지 말 것
- duration = 씬 수 × 씬당 초 (예: 2씬 × 3초 = 6초)

## 6. 진행 확인과 결과 표시

- 생성 시작 후 사용자에게 모델/설정 요약을 알리고, 확인 요청이 오면 `jobs_wait`(15초 롱폴)로 상태 확인. 이미지는 1~2분, 영상은 3~5분 걸린다고 안내.
- 완료되면 `job_display`로 결과 위젯 표시 + 결과 URL(rawUrl)을 함께 텍스트로 제공.

## 7. 다운로드 안내

실행 환경의 네트워크 정책이 힉스필드 CDN(cloudfront.net) 접근을 차단하는 경우가 있어 파일을 직접 받아 보내줄 수 없다. curl로 재시도하지 말고, 결과 URL을 주면서 "브라우저에서 열어 우클릭 → 저장" 또는 위젯의 다운로드 버튼을 안내한다.

## 8. AD STUDIO 앱과의 연계

이 vault의 `01-Projects/adstudio-local/`에는 브리프 → 씬별 스토리보드/이미지/영상 프롬프트(한글·영문)를 생성하는 로컬 Vite 앱(AD STUDIO)이 있다. 사용자는 보통 이 앱에서 프롬프트를 만들어 붙여넣는다. 프롬프트가 미완성(문장이 중간에 끊김)이거나 패널 수 등이 실제와 안 맞으면, 앞뒤 맥락으로 자연스럽게 보완·수정한 뒤 사용하고 무엇을 고쳤는지 사용자에게 알린다.
