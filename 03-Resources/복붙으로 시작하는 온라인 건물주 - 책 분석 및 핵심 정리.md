## 한 줄 요약

**코딩을 못 해도, AI에게 "복붙"할 프롬프트만 있으면 구독형 SaaS(=월세 나오는 온라인 건물)를 지어서 배포·과금까지 할 수 있다**는 실전 가이드. 핵심 공식은:

```
아이디어 발굴 → BM(수익 구조) 설계 → PRD(건물 설계도) 작성 → 도구 세팅 → AI로 제작 → 배포 → 런칭
```

## 3부작 흐름 (체크리스트 기준 재구성)

### 1편 — 돈 되는 아이디어와 설계도
- **SaaS 개념**: "구독하는 프로그램". 돈 되는 SaaS 공통점 = 단순·반복·귀찮음·계속 써야 함
- **아이디어 발굴 4가지 방법**
  1. **크몽 역분석** — 디지털·자동화 카테고리 상위 상품 10개 → "자동화 가능?" 아이템 3개 → 리뷰 불만 = 개선 기회 → 건당 가격을 월 구독료로 환산 (건당 5만 원 → 월 9,900원 × N명)
  2. **숨고 수요 확인** — '자동화/관리/정리' 검색 → 반복 요청 카테고리 3개 (반복 = 자동화 기회)
  3. **ProductHunt 한국화** — 미국에서 뜨는데 한국에 없는 SaaS 3개 → 네이버·카카오·당근 연계 가능성 검토
  4. **유튜브 댓글 마이닝** — "이런 거 있으면 좋겠다" 댓글 10개 수집, 공감 많은 것 우선
- **검증 질문 3개**: ① 이 불편함을 얼마나 자주 겪나? (매일·매주면 구독 의지 있음) ② 지금 어떻게 해결하나? ③ 그 해결법의 가장 큰 불편은?
- **PRD 개념**: AI가 알아듣는 설계도. PRD 없이 개발 = 70시간·50만 원·완성도 60% vs PRD로 = 25시간·5천 원·95%. ERD(데이터 서랍장)·TRD(기술 재료 목록) 포함

### 2편 — 건물 구조 이해 + 도구 세팅
- 프론트엔드(외관: 레이아웃·컴포넌트·인터랙션·반응형) / 백엔드(관리실: DB) / 유지보수(환경변수=금고, API 키 노출 금지, 에러는 AI에 복붙, GitHub로 되돌리기)
- **추천 스택**: Cursor(AI 에디터) + Supabase(DB, 서울 리전) + Vercel(배포) + Git/GitHub + 토스페이먼츠(결제)
- 핵심 포인트:
  - Supabase·Vercel은 **MCP로 Cursor에 연결** ("20 tools enabled" 확인)
  - **토스페이먼츠는 사업자등록증으로 신청, 승인 1~2주 → 가장 먼저 신청해두기. 정기결제(구독)는 별도 신청 필수!**
  - 클라이언트 키/시크릿 키/웹훅 시크릿 3종 보관

### 3편 — 실제 제작 → 배포 → 런칭
1. PRD를 AI에 주고 지시: *"PRD.MD 파일 보고, Supabase MCP 통해 DB 만들고, 앱 완성해줘. 오류 있으면 고쳐줘."* — **'MCP' 키워드 필수**
2. 로컬 확인: `npm run dev` → localhost:3000
3. 기능 테스트: 회원가입/로그인 → Supabase Table Editor에 데이터 실시간 저장 확인 → MVP 3기능 작동
4. 결제 연동: 키 3종을 env.local에 → AI가 일회성 결제로 만들면 "정기결제 구독형으로 바꿔줘" 재지시
5. Vercel 배포 → **환경변수 5종 등록 후 반드시 Redeploy** (SUPABASE_URL, SUPABASE_ANON_KEY, TOSS_CLIENT_KEY, TOSS_SECRET_KEY, TOSS_WEBHOOK_SECRET)
6. 커스텀 도메인 구매·연결 (Vercel 안에서 BUY 가능, 연 단위 갱신)
7. 런칭 전 점검: 전 과정 E2E 테스트, PC/모바일 레이아웃, **테스트 키 → 라이브 키 교체(필수!)**, 3초 로딩, 지인 1명 테스트, 첫 고객 100명 채널 확정

## 부록 1 — 아이디어 → BM 1분 프롬프트 (전문)

> 아래 전체를 복사하고, 대괄호 [ ] 안만 내 상황으로 채운다.

```
당신은 10년 경력의 'SaaS 비즈니스 모델 설계 전문가'입니다.
수백 개의 스타트업 아이디어를 실제 수익이 나는 사업으로
전환시킨 경험이 있습니다.

나는 지금 막연한 아이디어 하나를 갖고 있습니다.
이걸 실제로 돈이 되는 SaaS 비즈니스로 만들고 싶습니다.
나의 [아이디어 정보]를 바탕으로, 지금 당장 실행 가능한
'SaaS 비즈니스 모델 설계서'를 만들어 주십시오.

[나의 아이디어 데이터]

내 아이디어 한 줄 요약:
"[예: 헬스장 PT 선생님이 회원 식단과 운동 기록을 한눈에 관리하는 앱]"

이 아이디어가 떠오른 이유 (어떤 불편함을 봤는가?):
"[예: PT 선생님인 친구가 회원 관리를 엑셀로 하는 걸 보고
너무 비효율적이라고 느꼈음]"

주요 사용자가 될 것 같은 사람:
"[예: 1인 PT샵 운영하는 트레이너, 필라테스 강사]"

현재 이 문제를 어떻게 해결하고 있는지:
"[예: 엑셀, 카카오톡 메모, 수기 노트]"

내가 생각하는 핵심 기능 1가지:
"[예: 회원별 운동 기록 + 식단 사진 자동 저장]"

[반드시 포함해야 할 SaaS 비즈니스 설계서]

1. 타깃 고객 정의 (Who)
이 서비스를 가장 절실하게 필요로 하는 사람은 누구인가?
그들이 지금 겪고 있는 핵심 고통 3가지를 구체적으로 서술하라.

2. 수익 모델 설계 (How to Make Money)
이 서비스로 돈을 버는 방법 3가지를 제시하라.
각각 무료/유료 플랜 구분, 월 구독료 가격대, 유료 전환을 유도하는
핵심 기능을 포함하라.
(예: 무료 플랜: 회원 5명까지 / 유료 플랜: 월 19,900원, 회원 무제한 + 자동 리포트)

3. 경쟁 분석 (Why Me)
현재 시장에 존재하는 유사 서비스 또는 대체재를 3가지 나열하라.
각각의 치명적인 약점을 지적하고, 내 아이디어가 그 틈새를
어떻게 파고드는지 설명하라.

4. MVP 기능 리스트 (What to Build First)
지금 당장 만들어야 할 핵심 기능을 딱 3가지만 추려라.
나머지는 전부 '나중에'다. 지금 당장 돈을 받을 수 있는
최소 기능만 정의하라.

5. 첫 고객 100명 확보 전략 (Go-to-Market)
광고비 0원으로 첫 고객 100명을 모으는 방법을 단계별로 설명하라.
온라인/오프라인 채널을 각각 1가지 이상 포함하라.

6. 이 아이디어의 치명적 약점 (Devil's Advocate)
이 사업이 실패할 수 있는 이유 3가지를 냉정하게 말하라.
그리고 각각의 대응 전략도 함께 제시하라.
듣기 좋은 말은 필요 없다. 냉정하게 말하라.
```

- 넣는 곳: 책 추천은 BON.AI(trybonai.com)의 **Business 버튼** (4대 AI 올인원, 프로모션 코드 `bestbonai` 20% 할인). ChatGPT/Claude/Gemini에 붙여넣어도 됨 — 부족하면 "더 구체적으로 설명해줘"로 보완

## 부록 2 — BM → PRD 1분 프롬프트

- 부록 1의 BM 설계서(6개 섹션 전부) **전체를 복사** → BON.AI **PRD 버튼**(Business와 별개 버튼)에 붙여넣기 → 15초~수분 대기
- 결과물: 기능 명세 + ERD + TRD + 화면구성도 + **개발 태스크 P0(필수)/P1(중요)/P2(개선)** 까지 포함된 PRD
- 다른 AI 사용 시: 1편 챕터 3 "PRD에 뭘 써야 하나?" 참고해 수동 제작
- **주의사항**
  1. BM이 부실하면 PRD도 부실하다 — 6개 섹션 구체성 먼저 확인
  2. 너무 추상적이면 추가 질문: "기능 명세를 더 구체적으로 작성해줘" / "데이터베이스 스키마를 테이블별로 보여줘" / "사용자 플로우를 단계별로 상세히 설명해줘"
- 완성된 PRD는 Cursor(또는 다른 AI 에디터)에서 `PRD.MD` 파일로 저장 후 개발 시작
